# King SaaS — Flutter App (Android, iOS, Web)

One codebase, two experiences: after login, `AuthState`'s role decides
whether go_router sends you to the Super Admin Console (`/admin`) or the
Academy Workspace (`/academy`) — see `core/router/app_router.dart`.

## What's here
- `core/auth/` — AuthState (login/logout, holds role + token) and the API client
- `core/router/app_router.dart` — the redirect logic that makes the login unified
- `core/theme/app_theme.dart` — shared look & feel (rounded pastel inputs, navy CTAs)
- `features/auth/login_screen.dart` — the one login screen for every role
- `features/super_admin/` — Super Admin Console shell + placeholder pages
- `features/academy_workspace/` — Academy Workspace shell, matches the
  existing King Chess Academy bottom nav (Home / People / Attendance /
  Expenses / More)
- `features/academy_workspace/more/more_menu_screen.dart` — the real
  "More" tab; only "Send WhatsApp Message" is wired up, the rest are
  stubs for later phases
- `features/academy_workspace/messages/send_message_screen.dart` —
  compose a custom message, pick specific students or "select all",
  send. Needs `app/routers/messages.py` on the backend, which in turn
  needs a one-time WhatsApp template approval — see backend/README.md
  before expecting an actual message to land on someone's phone

## Important — read before running
This `lib/` folder and `pubspec.yaml` were hand-written, not generated by
`flutter create` (no Flutter SDK in the sandbox that built this). Before
it will run:

1. In an empty folder with the Flutter SDK installed: `flutter create .`
   — this generates the android/, ios/, web/, etc. platform folders
2. Copy this `lib/` and `pubspec.yaml` into that folder, overwriting the
   generated ones
3. `flutter pub get`
4. `flutter run -d chrome` for web, or `flutter run` for a connected
   device/emulator
5. Point it at your API: `flutter run --dart-define=API_BASE_URL=http://your-api-host:8000`
